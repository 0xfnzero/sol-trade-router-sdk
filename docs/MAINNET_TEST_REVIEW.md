## Fee rounding and AMM inverse follow-up

Three numeric defects were reproduced in existing tests. First, Router fees round down but the clamped-input budget inverse used the ceiling-fee formula: a spend of 1 at 1 bps returned gross 2 rather than 1. The same mismatch affected LaunchLab graduation-clamped inputs: with 100 actual quote units and a 100-bps Router fee, the old builder declared 102 although swap plus fee debited only 101, failing exact-input spend equality. The inverse now computes `floor((spend - 1) * 10000 / (10000 - bps)) + 1`, returns errors for unrepresentable inputs/rates, and preserves the smallest gross input. The existing high-level fee test verifies a synthetic graduation-clamped LaunchLab quote with actual spend 100, encoded budget 101 and fee 1.

Second, AMM V4 inverse quotes saturated overflowing inputs to `u64::MAX` and could return success even when that input did not reach the output target. They now reject unrepresentable net/gross input before narrowing or fee multiplication. Forward and inverse quotes also reject effective input reserve plus gross input overflow, a necessary vault-capacity condition (not a guarantee about unexposed full vault/PnL state). The ceiling-fee inverse matches official Raydium AMM V4 `swap_token_amount_base_out` and swap fee math; an existing test now checks 600 combinations across both directions and fee fractions, including near-100% fees, minimality, valid large inputs and unreachable/overflow cases.

Third, the program's fee multiplication used u64 and rejected large budgets even when the final fee fit u64, unlike the SDK's u128 calculation. The existing program budget test reproduced the mismatch for `u64::MAX` at 25 bps. The program now uses a u128 intermediate and checked final narrowing, preserving arithmetic errors when the final fee itself exceeds u64. Existing budget, mint and settlement checks are unchanged. This source change has not been deployed.
